① 模块一：认证鉴权（JWT）

这是整个项目最该讲清的一块，也是考核里"权限控制"的硬指标。先建立一个关键认知：

为什么不用传统的 Session，而用 JWT？
传统做法是登录后服务器开一个 session 存"谁登录了"，再给浏览器一个 cookie。问题是：服务器要存每个用户的会话状态，多台服务器就难同步。本项目用 JWT：登录成功后服务器不存任何状态，只发给你一个"签名过的令牌"，令牌里自带用户名和角色；之后你每次请求都带着它，服务器验一下签名就知道你是谁。这叫无状态（stateless）鉴权，方便以后横向扩展成多台服务器。

文件清单与职责

文件角色一句话职责
JwtUtil.java工具生成 token、校验 token 取出用户名
JwtFilter.java过滤器每个请求进来先拦，验 token 后把用户放进安全上下文
SecurityConfig.java配置规定哪些接口要登录、哪些放行、CORS、无状态
UserDetailsServiceImpl.java服务告诉 Spring Security：用户存在哪、密码是什么、什么角色
GlobalExceptionHandler.java异常处理业务抛的异常统一转成 400 + 提示，而不是 500/403
AuthController.java / UserService.java接口+业务注册、登录两个接口

核心代码 1：JwtUtil —— 签名与验签

// 生成 token：把用户名和角色写进去，用 HS256 + 密钥签名
public String generateToken(String username, String role) {
    return Jwts.builder()
        .setSubject(username)
        .claim("role", role)
        .setIssuedAt(new Date())
        .setExpiration(new Date(System.currentTimeMillis() + expiration))
        .signWith(getKey(), SignatureAlgorithm.HS256)
        .compact();
}
// 校验 token：用同一把密钥验证签名，返回用户名；签名不对就抛异常
public String validateAndGetUsername(String token) {
    Claims claims = Jwts.parserBuilder()
        .setSigningKey(getKey()).build()
        .parseClaimsJws(token).getBody();
    return claims.getSubject();
}
你怎么讲："token 本质上是一段被加密签名过的字符串，里面写了'这是谁、什么角色、何时过期'。服务器用私钥签名，别人改不了；以后每次请求服务器只要验证签名，就能相信 token 里的信息，所以不用在服务器存登录状态。"

核心代码 2：JwtFilter —— 每个请求都过这道关

protected void doFilterInternal(HttpServletRequest request, ...) {
    String header = request.getHeader("Authorization");
    if (header != null && header.startsWith("Bearer ")) {
        String token = header.substring(7);
        try {
            String username = jwtUtil.validateAndGetUsername(token);
            UserDetails ud = userDetailsService.loadUserByUsername(username);
            // 把登录用户放进安全上下文，后面 Controller 才能取到"我是谁"
            SecurityContextHolder.getContext()
                .setAuthentication(new UsernamePasswordAuthenticationToken(ud, null, ud.getAuthorities()));
        } catch (RuntimeException e) { /* 无效 token：当匿名，交给 Security 拦截 */ }
    }
    chain.doFilter(request, response);
}
排错点：前端报 401/403，先看请求头里有没有 Authorization: Bearer xxx。常见坑：① token 没存上（登录后没写本地存储）；② 复制 token 时把 "Bearer " 前后的空格弄丢了；③ token 过期（本项目默认 24 小时）。

核心代码 3：SecurityConfig —— 放行规则

.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/auth/**").permitAll()   // 登录/注册不用鉴权
    .requestMatchers("/h2-console/**").permitAll()  // 数据库控制台
    .anyRequest().authenticated())                     // 其他一律要登录
.sessionManagement(sm -> sm.sessionCreationPolicy(STATELESS)) // 无状态
http.addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
你怎么讲："我在配置里把 /api/auth/** 设为放行，因为登录前你还没有 token；其余所有接口都要求已认证。并声明了 session 策略为无状态，配合上面的 JWT 过滤器工作。"

核心代码 4：UserService.login —— 业务串联

public AuthResponse login(LoginRequest req) {
    authenticationManager.authenticate(           // 1. 让 Spring Security 校验账密
        new UsernamePasswordAuthenticationToken(req.getUsername(), req.getPassword()));
    User user = userRepository.findByUsername(req.getUsername()).orElseThrow();
    String token = jwtUtil.generateToken(user.getUsername(), user.getRole()); // 2. 签发
    return new AuthResponse(token, user.getUsername(), user.getRole());
}

注册时密码用 BCryptPasswordEncoder 加密后才入库，所以数据库里看到的是乱码一样的哈希值，不是明文——这是安全底线，也是信安专业该点出来的点。

排错点：登录一直失败，先确认数据库里密码是 BCrypt 哈希（应以 $2a$ 开头）。如果直接往库里插明文密码，BCrypt 一定比对不上。

② 模块二：分层架构（Controller / Service / Repository）

学长强调过：要理解"各层职责、各层如何协作"。这一块就是回答这个问题的。

为什么要分层？
如果不分层，所有代码（接请求、算业务、存数据库）全堆在一个方法里，改一处容易炸一片。分层后各管一摊：
  • Controller（接口层）：只管"接收请求、返回结果"，不写业务。
  • Service（业务层）：写业务规则和权限判断，是项目的"大脑"。
  • Repository（数据层）：只管"和数据库打交道"，由 JPA 自动实现，基本不用写 SQL。
  • Entity（实体）：数据库表的 Java 映射，一张表对应一个类。

实体：User / Textbook（对应两张表）

// User.java 对应 users 表
@Entity @Table(name = "users")
public class User {
    @Id @GeneratedValue(strategy = IDENTITY) private Long id;
    @Column(unique = true, nullable = false) private String username;
    @Column(nullable = false) private String password;   // 存的是 BCrypt 哈希
    private String role = "USER";
}
// Textbook.java 对应 textbooks 表，@ManyToOne 表示"一本教材属于一个用户"
@ManyToOne(fetch = LAZY) @JoinColumn(name = "owner_id")
private User owner;   // 发布者，外键关联 users 表

数据层：Repository（几乎零代码）

public interface TextbookRepository extends JpaRepository<Textbook, Long> {
    List<Textbook> findByOwnerId(Long ownerId);   // 方法名即查询，JPA 自动实现
}

你只要写方法名（findByOwnerId），Spring Data JPA 就自动生成 SQL。这是"约定优于配置"。

业务层：BookService（权限判断写在这里）

public Textbook create(Textbook textbook, String username) {
    User owner = userRepository.findByUsername(username).orElseThrow(...);
    textbook.setOwner(owner);              // 自动把当前登录人设为发布者
    textbook.setStatus("AVAILABLE");   // 新发布默认"在售"
    return textbookRepository.save(textbook);
}
public void delete(Long id, String username) {
    Textbook tb = textbookRepository.findById(id).orElseThrow(...);
    if (tb.getOwner() == null || !tb.getOwner().getUsername().equals(username))
        throw new RuntimeException("只能删除自己发布的教材");  // 权限校验
    textbookRepository.deleteById(id);
}
你怎么讲："权限控制不是只靠登录，而是在业务层再做一遍归属判断。比如删除教材，我先查出这条记录，确认它的拥有者就是当前登录人，否则拒绝。这样即使有人猜到别人的教材 ID，也删不了。"

接口层：BookController（从 Authentication 取当前用户）

@PostMapping
public Textbook create(@RequestBody Textbook textbook, Authentication authentication) {
    return bookService.create(textbook, authentication.getName()); // getName() 就是登录用户名
}
@GetMapping("/me")
public List<Textbook> listMine(Authentication authentication) {
    return bookService.listMine(authentication.getName());
}
学会标准：能说出"Controller 不写业务，只接收和转发；Service 写规则和权限；Repository 只碰数据库；Entity 是表结构"。
学好标准：能画出从浏览器到数据库的调用链，并解释为什么删除要在 Service 层判断归属而不是在 Controller 或前端判断。

③ 模块三：前后端联调

后端讲完，再看前端三件套：它们共同解决了"登录态怎么保存、请求怎么自动带 token、没登录怎么被拦回登录页"。

1) request.js —— 统一请求 + 自动带 token + 拦截异常

// 请求拦截器：发请求前自动把 token 塞进请求头
request.interceptors.request.use(config => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
// 响应拦截器：后端说 401/403（未登录或没权限），清掉本地状态并跳登录页
request.interceptors.response.use(res => res.data, err => {
  if (err.response && [401,403].includes(err.response.status)) {
    localStorage.removeItem('token'); window.location.href = '/login';
  }
  return Promise.reject(err);
});
排错点：页面一直跳回登录页——八成是 token 丢了或过期；或者后端返回的是 403 但你以为应该是 200。打开浏览器 F12 → Network，看请求头里到底有没有 Authorization。

2) auth.js —— Pinia 全局登录状态

export const useAuthStore = defineStore('auth', {
  state: () => ({ token: localStorage.getItem('token') || '', username: ..., role: ... }),
  getters: { isAuthenticated: s => !!s.token },
  actions: {
    async login(username, password) {
      const data = await request.post('/auth/login', { username, password });
      this.token = data.token; localStorage.setItem('token', data.token); // 同时存内存和本地
    },
    logout() { this.token = ''; localStorage.removeItem('token'); }
  }
});

注意：token 同时存了内存（Pinia）和本地存储两份。本地那份保证刷新页面后还登录着；内存那份供组件实时读取。

3) router/index.js —— 路由守卫

router.beforeEach((to, from, next) => {
  const auth = useAuthStore();
  if (to.meta.auth && !auth.isAuthenticated) next('/login'); // 标记要登录的页，未登录就踢回
  else next();
});
你怎么讲（一次发布的完整数据流）："我在发布页填表单 → axios 把数据 POST 到 /api/books，拦截器自动在请求头加上 Bearer token → 后端 JwtFilter 验过令牌，Controller 从安全上下文拿到我的用户名 → Service 把这条教材的拥有者设成我、状态设成在售 → Repository 存进数据库 → 返回新记录，前端刷新列表。整个过程前端不用关心'我是谁'，后端自己从 token 里认出来。"
